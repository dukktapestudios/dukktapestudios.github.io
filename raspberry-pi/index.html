1. What a Raspberry Pi is

A Raspberry Pi is a credit-card-sized computer. It runs a full Linux OS (Raspberry Pi OS), has USB, HDMI, Wi‑Fi, and a row of GPIO pins so you can talk to sensors, cameras, relays, and motors — like a tiny PC that can also control physical things.

Official list prices from raspberrypi.com (board only; accessories extra). Street prices at approved resellers may vary.

2. Getting started

You need: the Pi board, a microSD card (16GB+; 32GB is comfortable), a proper power supply (USB‑C for Pi 4/5; micro‑USB for Zero 2 W — use the official or a quality 5V supply), and optionally a monitor/keyboard for first boot.

Flash the OS with Raspberry Pi Imager

  1. Download Raspberry Pi Imager on your PC.
  2. Choose OS → Raspberry Pi OS (Desktop or Lite if you’ll go headless).
  3. Choose your microSD card → Write. Wait until it finishes.

Headless SSH setup (no monitor)

In Imager, open the gear / OS Customisation before writing:

  • Set hostname, username, and password
  • Configure Wi‑Fi (SSID + password) for your home network
  • Enable SSH

Insert the card, power the Pi, wait ~1–2 minutes, then from your PC:

ssh youruser@raspberrypi.local (or the IP from your router)

Enable the camera interface

Modern Raspberry Pi OS uses libcamera. After SSH (or on the desktop):

  • Connect the camera ribbon (contacts toward the right pins; Zero needs a Zero camera cable).
  • Run sudo raspi-config → Interface Options → enable Camera / legacy as prompted, or ensure the camera is detected.
  • Test: rpicam-hello or libcamera-hello (a short preview / still).

Pi 5 / newer boards: use the Camera Module 3 (~$25 official) with the correct ribbon for your model.

3. What you can do (and rough cost)

  • Camera / live video to phone — stream with motionEye, go2rtc, or a simple MJPEG/WebRTC page you open on your phone. Cam ~$25 + Pi
  • GPIO sensors — temperature (DS18B20, DHT), motion (PIR), door/window (reed switch), light, humidity. ~$2–15 each
  • Home automation — drive relays for lights/fans; talk to smart plugs via MQTT/Home Assistant. Relay boards ~$5–15
  • Networking — Wi‑Fi hotspot, reverse proxy, or a tiny personal web server. Software free
  • Media — Plex / Jellyfin client or server; RetroPie / Recalbox for classic games. Pi 4/5 preferred
  • Motors & servos — PWM on GPIO (or a HAT) for small DC motors and hobby servos. ~$3–20 + driver
  • SDR companion — plug in a cheap USB SDR dongle and decode radio with rtl-sdr / gqrx-style tools. Dongle ~$20–40

4. Worked example: chicken coop camera

Goal: see the coop from your phone without walking out there.

  • Board: Pi Zero 2 W (~$15) — small, Wi‑Fi, low power.
  • Camera: Camera Module 3 (~$25) + Zero camera ribbon.
  • Power: good USB 5V supply into the Zero; for outdoor, optional solar panel + battery / UPS HAT so it survives cloudy days.
  • Enclosure: weatherproof box with a clear window for the lens; keep vents from soaking the board.

How the stream reaches your phone

  1. Zero joins your home Wi‑Fi (set in Imager).
  2. Camera software (e.g. motionEye, go2rtc, or rpicam + a small web UI) serves a live page on the LAN.
  3. On your phone (same Wi‑Fi): open http://coop.local:port or the Pi’s IP.
  4. Away from home: use a VPN into your network, Tailscale/WireGuard, or a reverse tunnel — don’t expose the cam raw to the public internet.

Optional ESP32 nodes (temp, door open) can sit next to the coop and report over Wi‑Fi while the Zero handles video — see the Pi → ESP32 section below.

5. Learning path

1. Blink an LED → 2. Camera still / stream → 3. One sensor → 4. Relay / automation
  1. Blink an LED — wire LED + resistor to a GPIO pin; toggle it with a few lines of Python (gpiozero). Proves power, pins, and code.
  2. Camera — take a still, then a short stream. You’re already “seeing” the world.
  3. Sensors — read temperature or a door switch; print values or log them.
  4. Automation — if temp high → fan relay on; if door open after dark → notify. Small scripts beat big frameworks at first.

Official docs: raspberrypi.com/documentation

Magazine: The MagPi (free PDF issues — project-heavy, beginner-friendly).

6. Building Up: From Pi to ESP32

The Pi’s GPIO pins are the same doorway as the ESP32 — same 3.3V logic, same pin-control concepts — so skills transfer directly.

What transfers

  • Reading sensors (temperature, motion, door switches)
  • Driving LEDs and relays
  • PWM for motors and servos
  • Writing the software that ties it together

The upgrade path

Start on the Pi (easier to see results, full Linux desktop/SSH). Then move to ESP32 boards (~$5 each) for cheap, low-power, battery/solar projects — same code patterns, just a different library (Arduino / ESP-IDF / MicroPython instead of gpiozero on Linux).

The ESP32 also adds Wi‑Fi and Bluetooth built in, which is why it’s the go-to for remote sensor nodes — like companion sensors next to a coop camera.

Bottom line: the Pi teaches you the concepts; the ESP32 lets you scatter cheap nodes everywhere.

7. Examples (hands-on)

Each one teaches one idea. Parts are typical; pin numbers are examples — check your board’s pinout.

1. Blink an LED

What it does: Turns an LED on and off on a timer so you know GPIO + code work.

Parts: LED, 220–330Ω resistor, jumper wires, breadboard.

Key concept: A GPIO pin is a software-controlled on/off switch (3.3V when high).

from gpiozero import LED
from time import sleep

led = LED(17)  # BCM pin 17
while True:
    led.on()
    sleep(0.5)
    led.off()
    sleep(0.5)

2. Read a temperature sensor

What it does: Prints the room (or coop) temperature every few seconds.

Parts: DS18B20 (1-Wire) or DHT22; for DS18B20 enable 1-Wire in raspi-config.

Key concept: Sensors speak a protocol; your code asks for a reading and converts raw bits to °C/°F.

# DS18B20 via gpiozero (1-Wire enabled)
from gpiozero import CPUTemperature  # demo: CPU sensor always available
from time import sleep
# For a real DS18B20 use w1thermsensor or read /sys/bus/w1/...
t = CPUTemperature()
while True:
    print(f"{t.temperature:.1f} °C")
    sleep(2)

Swap CPUTemperature for your probe library once the sensor is wired (data pin + 4.7kΩ pull-up for DS18B20).

3. Read a motion sensor (PIR)

What it does: Prints “motion!” when someone walks past a PIR module.

Parts: HC-SR501 (or similar) PIR, 5V power from Pi, signal to a GPIO input.

Key concept: Digital inputs are either high or low — poll them or wait for an edge.

from gpiozero import MotionSensor

pir = MotionSensor(4)  # BCM 4
pir.when_motion = lambda: print("motion!")
pir.when_no_motion = lambda: print("quiet")
from signal import pause
pause()

4. Detect motion with the Pi camera

What it does: Compares frames and saves a still when enough pixels change.

Parts: Camera Module 3 (or 2) + correct ribbon for your Pi.

Key concept: Vision motion = difference between frames, not a PIR — lighting changes can false-trigger.

# Sketch: capture, compare, save on change (use picamera2)
from picamera2 import Picamera2
from PIL import ImageChops, Image
import time

picam = Picamera2()
picam.start()
prev = picam.capture_image("main").convert("L")
while True:
    time.sleep(0.5)
    cur = picam.capture_image("main").convert("L")
    diff = ImageChops.difference(prev, cur)
    # if enough bright pixels in diff → motion
    if diff.getbbox():
        cur.save("motion.jpg")
        print("saved motion.jpg")
    prev = cur

5. Pan-tilt tracking with two servos

What it does: Moves a camera mount left/right and up/down to follow a detected blob.

Parts: Two hobby servos, pan-tilt bracket, external 5V for servos (don’t power servos from Pi 3.3V pins), common ground.

Key concept: PWM sets servo angle; tracking = find target in frame → adjust pan/tilt toward center.

from gpiozero import AngularServo
from time import sleep

pan = AngularServo(17, min_angle=-90, max_angle=90)
tilt = AngularServo(27, min_angle=-45, max_angle=45)

def aim(dx, dy):
    # dx/dy = how far the target is from frame center (pixels)
    pan.angle = max(-90, min(90, (pan.angle or 0) + dx * 0.05))
    tilt.angle = max(-45, min(45, (tilt.angle or 0) + dy * 0.05))

# Call aim() from your vision loop after finding the target
aim(20, -10)
sleep(1)

6. Push a photo or stream to your phone over Wi‑Fi

What it does: Serves a live page on your LAN that your phone opens in a browser.

Parts: Pi on Wi‑Fi, camera optional; phone on the same network.

Key concept: The Pi is a tiny web server; your phone is just a client. For away-from-home, use a VPN — don’t expose the cam raw to the internet.

# Simplest still server (Flask sketch)
from flask import Flask, send_file
from picamera2 import Picamera2

app = Flask(__name__)
cam = Picamera2()
cam.start()

@app.get("/")
def index():
    cam.capture_file("/tmp/shot.jpg")
    return send_file("/tmp/shot.jpg", mimetype="image/jpeg")

app.run(host="0.0.0.0", port=8080)
# Phone: http://raspberrypi.local:8080

For continuous video, use motionEye, go2rtc, or rpicam-vid piped to a streamer.

7. Control a relay (mains — safely)

What it does: Lets the Pi switch a light or heater through a relay module, never by touching AC wires to GPIO.

Parts: Opto-isolated relay board rated for your load; Pi GPIO to relay IN; mains only on the relay’s screw terminals inside a covered box. Or skip AC and use a Wi‑Fi smart plug via MQTT.

Key concept: The Pi only drives a low-voltage signal; the relay’s contacts handle mains. Common ground + correct active-high/low for your board.

from gpiozero import OutputDevice
from time import sleep

# Many relay boards are active-LOW
relay = OutputDevice(17, active_high=False, initial_value=False)
relay.on()   # load ON
sleep(5)
relay.off()  # load OFF
Safety: If you’re unsure about AC wiring, don’t. Use a listed smart plug and control it over the network instead.

8. Safety

3.3V only on GPIO. Pi pins are 3.3V logic. Do not feed them 5V signals. Level-shift or use 3.3V sensors. Shorting a pin the wrong way can kill the board.

  • Mains / relays: never wire household AC directly to the Pi. Use a properly rated relay module or smart plug; keep mains in a covered enclosure. If you’re unsure about AC wiring, don’t — use Wi‑Fi plugs instead.
  • Power supplies: underpowered or junk chargers cause random crashes and SD corruption. Prefer official or quality 5V supplies rated for your model (Pi 5 wants a solid 5A-capable USB‑C PD supply).
  • ESD: touch grounded metal before handling the bare board; avoid working on carpet in socks. Store boards in antistatic bags when not in use.
  • Heat & outdoors: Pi 5 likes a cooler/fan under load. Outdoor boxes need drip protection and condensation awareness.
