Make a small iPhone app, then learn the App Store

This is a practical course for someone starting from zero. You will build a tiny checklist called One Small Win, first in this browser, then as an Expo project you can later submit to Apple. Finishing the steps means you did the steps. It does not mean Apple will approve the app, that the app will earn money, or that a review will finish on a particular day.

The browser checklist on this page was exercised in a desktop browser. The Expo and Swift files were checked for internal consistency and were not compiled, signed, or submitted to Apple from the computer that published this course. Where a button label or price can change, the linked official page wins over this text.

01The first hour, on this page

An iPhone app is a program installed on an iPhone, with its own icon, that a person opens without going through a browser address bar. You do not need a Mac, an Apple Developer membership, or a store listing to learn the shape of one. Those show up later, and some of them cost money. This hour is free and stays in your browser.

One Small Win is a fictional checklist. You type one concrete thing, you see it, you mark it done, and you still see it after a refresh. Version 1 has no account, no payment, and no location. That keeps the first version inside what you can understand and test.

Minutes 0 to 15: use the practice app

The panel below is the product, shrunk to a browser. Your list is stored with localStorage on this computer. This page has no form that sends your list anywhere.

The practice app loads with the page script. If you still see this sentence, the script did not run. You can keep reading. The same behavior is described in the checkpoints.

  1. On Today, type Put the mug in the sink and press Add win.
  2. You should see that sentence in large type and the status 1 still open.
  3. Open All wins. Press the sentence. It gains a line through it. Today should then say 0 still open and show the empty sentence again.
  4. Refresh this page. Open All wins. The mug line should still be there. That is persistence: the data survived a restart of the page.
  5. Press Remove, then Erase list on this browser. The empty sentence returns. That is the empty state, and it is a real screen, not a failure.

Checkpoint. If refresh keeps the line, you have already built the core of version 1: capture one item, show it, change it, and keep it. The rest of the course is how to put that behavior on an iPhone and, later, in the store.

Minutes 15 to 35: name the three screens

On paper or in the notes box, write three titles: Today, All wins, About. Under Today, write what the person sees with zero items, with one open item, and when the text is blank. Under About, write one honest sentence: the list stays on the device. Leave payments and accounts out. A first app that tries to do those on day one usually stalls on accounts, legal text, and review questions you do not need yet.

Notes stay in this browser.

Minutes 35 to 60: decide the machine you have

If you have Windows, you can write the app and preview it in a browser. You can also use an Android phone as a learning device. You cannot install Xcode on Windows, and Windows cannot run Apple's iOS Simulator. A finished iOS binary still has to be built on Apple's operating system. Expo's cloud build service does that build for you later, after you choose to spend the Apple membership fee.

If you have a Mac, you may follow the same Expo route. A separate section later shows a SwiftUI version for people who want Xcode. Do not mix the two sets of commands in one project.

Stop here if you want. You have a working checklist and a written screen list. That is a complete first session. Come back for the install when you have an hour and a computer you can restart.

02Words, the first time you need them

People quit app tutorials because the words pile up. Here each word is tied to One Small Win. The glossary at the bottom repeats them in a table you can filter.

Source code
The text you edit. For this project it is files such as index.tsx and wins.ts. The phone does not run those files directly. A build turns them into an installable app.
Frontend
The part a person sees and touches: the title, the text field, the buttons. In One Small Win the frontend is the three screens.
Backend
A program on a server that your app calls. Version 1 has no backend. The list lives on the device. Add a backend when two people must share the same list, or when a secret must stay off the phone.
API
A published way for one program to ask another program to do something. An App Store app might call your server's API. Apple also has APIs, which are the system functions your app is allowed to use, such as saving a file.
Database
An organized store of records. On the phone, version 1 uses a small local store (browser storage here, AsyncStorage in the Expo project). A database on a server is a later choice, not a requirement for a private checklist.
Native app
An app written with the platform's own tools. For iPhone, that means Swift and Xcode on a Mac. The system draws the buttons.
Cross-platform app
One project that can produce an iPhone app and an Android app. This course uses Expo, which sits on React Native. You still ship a real iOS binary to Apple. The Android store is a different company, a different fee, and a different review.
Website and PWA
A page in a browser. A progressive web app can be saved to a home screen from the browser. That install is not an App Store install. Apple does not review it, and it does not appear in the App Store.
Simulator
A Mac program, included with Xcode, that pretends to be an iPhone. It is useful. It is not a physical phone, and it does not exist for Windows.
Build
The packaged app file. For the store, the iOS file is an .ipa. Making it requires Apple's build tools, either on a Mac or on a Mac that a cloud service runs for you.
Signing
Apple's way of marking who built the app and which app ID it is. A signed build is what TestFlight and the App Store will accept. Expo can create the signing files after you sign in with a paid Apple Developer membership. Apple still issues them.
Bundle ID
A unique name for the app, usually written like a backwards domain: app.example.onesmallwin. The example string is a placeholder. After you upload a build, Apple's documentation says you cannot change the bundle ID.
TestFlight
Apple's beta app. Testers install your signed build from TestFlight before, or instead of, the public store.
App Store Connect
The website where you create the store record, answer privacy questions, upload screenshots, pick a build, and submit for review. The public App Store is what customers see after release.

04The route this course follows

The recommended route is Expo, because a Windows computer can edit and preview the app, and Expo's submit documentation says eas submit works on Windows, Linux, and macOS. You still need a paid Apple Developer Program membership before a production iOS build can be signed for the store. Cloud signing does not remove Apple review.

There are three different iOS runtimes in Expo. Keep them apart:

  • Expo Go is a playground app already on the store. Expo's own setup page calls it a place for students to try Expo quickly, and says it is limited and not the environment for a production project. It includes one SDK version. If your project uses another SDK, the phone shows an incompatible-project error. Expo Go does not use your final bundle ID, and behavior around notifications, maps, and other native configuration can differ from the app you will ship.
  • A development build is your own app, installed on a phone, with Expo's developer tools inside it. It can include native libraries that Expo Go does not contain. Creating one for a physical iPhone uses a signing path and, for a store-style install, the paid program.
  • A production build is the optimized .ipa you upload. Expo's production tutorial says this build is distributed through App Store Connect, not by dragging a file onto the phone. TestFlight and the store come after that upload. Apple still reviews the first external TestFlight build and the store submission.

On 8 November 2026, Expo's create-a-project page and its Expo Go mismatch page do not describe the same store build of Expo Go. The create page says that during the SDK 58 transition, create-expo-app@latest without a template creates an SDK 57 project, and that SDK 57 is the one to use if you plan on Expo Go on a physical device. The mismatch page says the App Store copy of Expo Go stops at SDK 54, and that SDK 55 and later are not in that store build. Both pages are linked below. When you start, read them again. If the phone rejects the project, stop changing version numbers and use a path that page lists: the web preview, an Android device, the iOS Simulator on a Mac, a development build, or eas go through TestFlight. eas go needs the paid Apple program.

The Mac-only route, kept separate

Choose this only if you will edit in Xcode. Apple's system requirements page lists Xcode 27.2 as a released version that runs on macOS Tahoe 26.6 or later, with the iOS 27.2 SDK. Download Xcode from the Mac App Store or from Apple's developer downloads. The iOS Simulator is part of that install. A sample SwiftUI checklist is in starter/mac/ContentView.swift. It was not built on a Mac here. Put it in a new iOS App target that uses SwiftUI, run it with Xcode's run button, and use Apple's distribution document when you archive. Do not install Expo commands into that Xcode project.

05Pick a tiny idea and write one page

A useful first app helps one person finish one job in under a minute. One Small Win does that: capture a task small enough to do today. Your own app can replace the noun. A packing list, a medication reminder you personally understand, or a rehearsal log are the same shape. Leave out anything that needs another company's data, a map, or a login.

Write a one-page spec before you install anything. The template is in the templates section. Fill it with fictional sample tasks, never a real address, account, or private phone number. Apple's review guideline 2.3.9 says screenshots should use fictional account information.

Reject the idea for version 1 if any line is true: it needs a payment to be useful, it is mostly a link to a website, it copies another app's name or screens, or you cannot explain the success test in one sentence. The success test for One Small Win is: after a force-quit, the last added line is still there.

Checkpoint. You can hand the page to someone else and they can tell you whether the app is done without asking what you meant.

06Three screens

Today. One open win, a text field, Add. All wins. Every line, done, or remove. About. Where data lives, and later the privacy link. Back. The system back control returns to Today.

Three screens are enough. A tab bar, accounts, settings, and themes can wait until the three screens work. Draw the empty, filled, and error versions of Today on the same sheet. The error version for version 1 is a sentence: the text was empty, or the phone could not save.

Navigation means how someone moves between those screens. In the Expo project, Expo Router treats files in src/app as screens. index.tsx is Today. list.tsx is All wins. about.tsx is About. _layout.tsx stacks them and gives each a title. That is the whole map.

07Set up Windows or Mac

Expo's create-a-project page lists the system requirement as Node.js LTS, on macOS, Windows (PowerShell and WSL 2), or Linux. Install the current Long Term Support installer from nodejs.org. This course does not pin a version number beyond that, because Expo's page says LTS and a later SDK can raise the minimum. If the create command prints a Node version error, install the version that error names.

Install Git from git-scm.com/downloads. On Windows, the Git installer includes Git Bash. PowerShell is enough for the commands below. Close and reopen the terminal after installing so the new commands are on the path.

node -v
npm -v
git --version

You want three version lines, not the words "not recognized". If Windows says the command is not recognized, the installer did not change the path for this window. Open a new terminal. If it still fails, re-run the Node installer and leave "Add to PATH" selected.

Create a folder whose name has no spaces, for example C:\apps or ~/apps. You will create the project inside it in the next section. Do not put the project in a folder that syncs every file to a cloud drive if you can avoid it. Those tools lock files while npm is writing them, and the error looks like a random crash.

Checkpoint. node -v prints a version. You have not paid Apple. You have not created a store record. That is the correct place to be.

08Construct One Small Win

The commands in this section are the Expo route. They were not executed against Apple's build service here. Run them on your machine and compare what you see with the notes.

Create the project

From the folder you chose, run one of these. Use the first if you want the physical-device Expo Go path described on Expo's create page during the SDK 58 transition. Use the second if you are going to preview in a browser, use a simulator, or make a development build.

npx create-expo-app@latest one-small-win
npx create-expo-app@latest one-small-win --template default@sdk-58

npx downloads the creator, asks permission the first time, and writes a folder named one-small-win. When it finishes, the terminal returns to a prompt. Expected contents include package.json and a src/app directory. Expo's start-developing page, checked 8 November 2026, says the default template's routes are src/app/index.tsx, src/app/explore.tsx, and src/app/_layout.tsx. If your folder has app/ at the root instead of src/app/, follow the folder you actually have. The course files assume src/app.

Replace the sample screens

cd one-small-win
npx expo install @react-native-async-storage/async-storage

npx expo install picks a library version that matches the SDK you just created. A plain npm install of a random version is how projects get the incompatible-SDK error later.

Copy these files from this course into the project, overwriting the template files with the same names. Delete src/app/explore.tsx if it exists so the old sample tab is gone.

  • starter/src/app/_layout.tsx
  • starter/src/app/index.tsx
  • starter/src/app/list.tsx
  • starter/src/app/about.tsx
  • starter/src/lib/wins.ts

The screen files import ../lib/wins. That path works when wins.ts is at src/lib/wins.ts and the screens are in src/app/. The rules match the browser lesson: blank text is refused, and text longer than 120 characters is refused.

See it in a browser

Expo's web guide says to start the browser with:

npx expo start --web

If the CLI offers to install web packages, the web guide's install command is:

npx expo install react-dom react-native-web @expo/metro-runtime

Expo's CLI page also lists the W key inside npx expo start as "open the project in a web browser". The same page still says that shortcut may require webpack. If W fails, use the --web command and the install line above rather than hunting an old webpack tutorial. A browser window should open on localhost. Expo's local HTTPS guide describes port 8081 as the dev server port. Your port can differ if 8081 is busy. The terminal prints the address. Use the address the terminal prints.

Expected screen: a dark page, the words "0 still open", the empty sentence, a text field, and Add win. Type a short line. It appears above the field. Reload the browser tab. The line remains. That is AsyncStorage in the web preview, which uses browser storage under the hood. It is the same product idea as the panel in section 1. It is still not an iPhone build.

Checkpoint. You changed files, started a dev server, and saw your sentence survive a reload. If the terminal shows an error instead, copy the whole error into the troubleshooting section's habit: read the file name, change one thing, run again. Do not start a second project to escape the message.

Open it on a phone, if the versions agree

npx expo start

The terminal shows a QR code. Expo's start-developing page says the phone and the computer need the same Wi-Fi, and that a physical iPhone running Expo Go must be signed into the same Expo account as the computer. On the computer that is npx expo login. In Expo Go, the account control is the icon in the top-right. If the network blocks the phone, the same page documents:

npx expo start --tunnel

Tunnel is slower. Use it when the LAN path fails, then go back. Press A for an Android emulator or device, or I for the iOS Simulator. I requires a Mac with Xcode. Windows will not open an iOS Simulator, and the CLI will say so in its own words if you press I there.

09State and saving on the device

State is the data the screen is showing right now. In Today, that is the list and the half-typed line. React keeps it in memory with useState. Memory disappears when the app process stops. Persistence is the extra step that writes the list to disk.

In index.tsx, addWin returns a new list. The screen then calls AsyncStorage.setItem with the key one-small-win-v1. On the next launch, getItem reads that key and parseWins throws away anything that is not a short checklist item. That second half matters. Saved data can be old, empty, or damaged. The app should show an empty list rather than a red crash.

Edit one string and confirm you understand the round trip. Change the empty-state sentence in index.tsx from "No open wins…" to "Nothing open yet." Save the file. Expo's start-developing page says Fast Refresh reloads the app when a file changes. You should see the new sentence without creating a new project. If you do not, shake the phone or press Cmd+D in the iOS Simulator for the developer menu, and toggle Fast Refresh the way that page describes. On web, reload the tab.

Checkpoint. You can point at the line that refuses a blank win, the line that writes storage, and the line that reads it back. Those three lines are the app.

10Edit, look, restart

Work in a loop small enough to remember. Change one behavior. Look at the screen. If it is wrong, read the first error, not the tenth.

  1. The red box or the terminal stack trace names a file and a line. Open that file.
  2. Read the sentence above the file name. "Unable to resolve module" means an import path does not match a file. "Project is incompatible with this version of Expo Go" means the SDK numbers differ. It does not mean your checklist logic is bad.
  3. Fix that one cause. Save. Look again.
  4. If the screen is stale, stop the server with Ctrl+C and run npx expo start --web again.

A useful bug note has four lines: what you clicked, what you expected, what you saw, and the exact error text. The bug-report template is below. Write it before you ask a person or a model for help. The writing often shows the mistake.

11Small tickets and AI help

A ticket is one change you can test. "Build my app" is not a ticket. These are tickets:

  1. Show the empty sentence when the list is empty.
  2. Refuse blank input.
  3. Keep the list after reload.
  4. Add a Remove button that asks the storage to update.
  5. Put a privacy-policy sentence on About.

Finish one, look at it, then commit it. An AI coding tool is useful on a ticket that already has a file name and a visible result. It is a poor designer of your whole product. Paste the prompt template. Include the error text. Tell it which files it may edit. Tell it not to add accounts, payments, or new libraries. Read the diff before you run it. You are responsible for the code you submit to Apple, including code a model wrote. Guideline 5.1.2 also requires explicit permission before personal data is shared with a third-party AI service. Do not paste your Apple password, a private key, or a stranger's personal data into a chat.

Checkpoint. You have a written ticket list, and the first ticket is already true on your screen. That is the working method, and it is worth more than a large generated project you cannot explain.

12Git backups and rollback

create-expo-app often creates a Git repository for you. Check before you create a second one:

git status

If Git says this is not a repository, run git init. Then save a known-good snapshot:

git add .
git status
git commit -m "Checklist saves a short win"

git status before the commit shows what will be saved. You want your source files. You do not want .env secrets, .p8 App Store keys, or .p12 certificates. If those names appear, do not commit them. Add the file name to .gitignore and leave the secrets out of the repository.

To throw away uncommitted edits in one file:

git restore src/app/index.tsx

To undo the last commit while keeping history, create a new commit that reverses it:

git revert HEAD

git reset --hard deletes uncommitted work. Do not use it as a habit. git log --oneline shows the snapshots you can return to. A remote host such as GitHub is a second copy if your disk fails. It is optional for learning and useful before you start paying for a membership, because the project is then not only on one laptop.

13A backend, only when you need one

Add a server when the success test requires it. Shared lists, accounts, and hidden API keys need a server. A private checklist does not. If you add one later, these are the rules to design in before you write the request:

  • Secrets, including database passwords and private API keys, live on the server. The phone receives only what that user may see.
  • Ask for the smallest permission that does the job. Guideline 5.1.1 (iii) is Apple's data-minimization rule. A checklist does not need contacts, photos, or location. If you later need a photo, the system picker is the smaller permission.
  • Say what you collect, in the privacy policy and in App Store Connect. Collecting nothing from the server is a real answer. You still disclose on-device storage if Apple's questionnaire asks about data stored on the device in a way you can access. Read the questions. Do not copy another app's answers.
  • If you add accounts, you take on deletion, password reset, and a demo login for review. Section 23 is the point to read before you build that.

This course does not include a backend project. Building one "just in case" is how a first app stalls.

14Images, fonts, and licenses

Version 1 can ship with text and Apple's system font. That avoids a license question. When you add an icon, a photo, or a font, write down who made it and which license you have. "I found it on a search page" is not a license. Guideline 5.2.1 requires you to have rights to third-party material. Guideline 2.3.9 says you are responsible for the rights in your icons, screenshots, and previews.

A practical rule: draw a simple mark yourself, or use a resource whose license explicitly allows an app icon. Keep the license file next to the image in your project. The About screen can credit it in one line. Do not use another app's icon, a company logo, or a celebrity photo.

15Loading, empty, offline, and error

Each screen needs a sentence for the moments that are not the happy path. One Small Win uses four:

  • Loading. "Reading saved wins…" while storage is opening. On a phone this can be fast. The sentence still matters when the disk is slow.
  • Empty. "No open wins. Add one small thing you can finish." This is the correct first launch. It is not an error.
  • Error. "Type a win first." or "The win is on screen. Saving it on this phone failed." Say what happened and what still works.
  • Offline. Version 1 does not use the network for the list, so airplane mode should still add and show wins. Test that on a phone before you claim it. If a later version fetches from a server, the offline sentence must say the list may be old.

In the practice panel, press "Read saved list again". The status tells you how many wins it read. That is the loading path with a visible result.

16Accessibility

A first app can be usable if you do a few concrete things. The starter screens use a real text input with a label, buttons that say what they do, and accessibilityLabel on the done and remove controls so the label includes the win text. The practice panel uses the same idea: a label on the field, buttons with names, and a status element that announces the count.

On your phone, turn on the largest text size in Settings and open the app. The win should still be readable and the button should still take a tap. Turn on VoiceOver, or TalkBack on Android, and move through Today. You should hear "Win to add" and "Add win", not "button" with no name. Apple's Human Interface Guidelines accessibility chapter is the reference for the platform behavior. Do not ship a control that only works with a color change. Done items in the starter also use a line through the text.

Expo Go counts as a learning test when the SDK matches. It does not count as the release test. The release test is the TestFlight build, because that build uses your bundle ID and your signing.

18The Apple Developer Program

You can write and preview for free. Putting the app in TestFlight or the App Store requires the Apple Developer Program. Apple's program page lists the membership at 99 USD per year. The enrollment page says the same annual fee, in local currency where available, and that prices may vary by region and are shown in local currency during purchase. Individuals who enroll in the Apple Developer app get an auto-renewable subscription until they cancel. Enrolling on the web uses the payment methods that page presents. If you enroll as an individual and pay by card, Apple says the card must be your own.

Individual or organization

This is a public-identity choice, not a styling choice. Apple's enrollment page says an individual or sole proprietor is listed on the App Store under their personal legal name. An alias, nickname, or company name in the name fields delays enrollment. An organization is listed under the legal entity name. Organizations must be a legal entity. Apple says it does not accept DBAs, fictitious names, trade names, or branches. The organization path asks for a D‑U‑N‑S Number, which Dun & Bradstreet assigns. Apple says those numbers are free in most jurisdictions and are not required for government organizations. The person enrolling needs legal authority to bind the organization, a work email on the organization's domain, and a public website that belongs to the organization. A thin social-media page does not qualify, according to that same enrollment page.

Identity verification asks individuals for a legal name, phone number, and address. Apple says post-office boxes are not accepted, and that some people are asked for a photo ID. That information is part of enrollment. It is not something you put in the app's screenshots. This course does not collect it.

Two-factor authentication

Apple's sign-in help says two-factor authentication is required for program Account Holders to sign in to their developer account. Two-factor authentication or two-step verification is required for every user of App Store Connect. Turn it on in the Apple Account's Sign-In & Security settings, or follow Apple's support article linked below, before you start enrollment. Have a trusted device available. Apple says it will not ask you for the six-digit code as a support trick. Do not give that code to a helper or paste it into a chat.

Fee waivers, and the program you do not want

Apple offers a fee waiver to qualifying nonprofits, accredited educational institutions, and government entities. Individuals, sole proprietors, and single-person businesses are not eligible. The waiver also requires that the organization not sell digital goods, including paid apps and in-app purchases. If you want to charge for the app later, do not plan on the waiver.

The Enterprise program is a different contract at 299 USD per year for private distribution inside a company. It is not how you publish One Small Win on the public App Store. Skip it.

Checkpoint. You can say, in one sentence, whose name will appear as the seller, and you know the annual fee shown to you at checkout may be 99 USD or the local price Apple displays. You still do not need to enroll to finish the browser and Expo preview work.

19Bundle ID, versions, and signing

Apple's bundle ID documentation says the ID may contain letters, numbers, hyphens, and periods, is case-insensitive, and is typically reverse-DNS. It must match the value in App Store Connect. After you upload a build, you cannot change it, and you cannot delete the explicit App ID tied to it. app.example.onesmallwin in the snippet is a teaching placeholder. Replace example with a string you control and that you are willing to keep forever. Uniqueness is the requirement that blocks you. Two apps cannot share it.

Open app.json if the template created JSON. If it created app.config.ts, set the same fields inside the exported object instead of pasting JSON into a TypeScript file. The teaching snippet is starter/app-json-snippet.json. Set version to 1.0.0. Set ios.bundleIdentifier. Set ios.supportsTablet to false for an iPhone-only first release so you are not also designing an iPad layout. If App Store Connect later asks for iPad screenshots, the binary you uploaded still supports iPad. Believe the upload page.

Apple's glossary, checked the same day, defines the version number (CFBundleShortVersionString) as three period-separated integers, such as 1.0.0. The build string (CFBundleVersion) is one to three period-separated integers. Customers see the version. App Store Connect uses the build string to tell uploads apart. When an upload is refused as a duplicate, increase the build string and build again. The first public version does not need a "What's New" text. Later versions do.

Who creates the certificates

Apple's technical note on provisioning profiles says a profile ties together who may sign, which app, where it may run, when, and which entitlements it gets. A distribution certificate identifies the developer account. A provisioning profile identifies the app. Expo's credentials page says Expo can generate the distribution certificate, the provisioning profile, and a push key when you run eas build and sign in with an Apple Developer Program membership. Expo stores those files and reuses them. You may also upload your own.

Read Expo's page when you do this, because two sentences on it are easy to mix up. The summary table lists a distribution-certificate limit of 2 per account, says the certificate is not app-specific, and says revoking it does not remove apps already on the store. Another sentence says you may only have one. If the page still disagrees with itself, trust the error you get when creation fails, and do not delete a certificate that you still need for an app already in review. Provisioning profiles on that page expire after 12 months. Existing store installs keep running. The next build needs a new profile.

One Small Win does not send push notifications. If a prompt is only about a push key, you can skip it. If you are unsure which prompt you are looking at, stop and read it. Signing in to Apple from the Expo CLI is the moment your Apple account password is involved. Use it on a computer you trust. Do not put the password in a file.

On an individual membership, Expo's roles page says only the Account Holder can generate signing credentials. On an organization membership, Account Holder and Admin can, and App Manager can when that user has access to Certificates, Identifiers & Profiles.

20The App Store Connect record

After the membership is active, sign in at App Store Connect and create an app record. You will be asked for the name, the bundle ID you already chose, and a SKU. Apple's app-information table says the SKU is an internal ID customers do not see. It can contain letters, numbers, hyphens, periods, and underscores, and it cannot start with a hyphen, period, or underscore. You cannot change the SKU later. A teaching SKU is one-small-win-001. Use your own.

The name customers see must be at least 2 characters and at most 30. "One Small Win" fits. The subtitle, if you use one, is also limited to 30 characters. The name should describe your app. Guideline 2.3.7 says not to stuff another app's trademark into the name or keywords to catch searches.

Expo's submit guide says eas submit can create the App Store Connect app if it does not exist yet, after you sign in with your Apple ID. Creating it yourself first is calmer, because you can read each field. Either way, the bundle ID in the project and the bundle ID on the record must be the same string.

21Icons and screenshots

Apple's Xcode icon document says an iOS app can generate the icon sizes from one 1024×1024 image placed in the iOS 1024pt image well. In the Expo route you do not open that well yourself. You put a 1024×1024 PNG at the path named by the icon field, and the cloud build packages it. Confirm the current Expo icon guide on the day you build, then confirm the asset Apple shows in App Store Connect. A tiny transparent gap around a glyph is a common rejection detail: Apple's screenshot specification says images cannot include an alpha channel, and you should treat the icon with the same caution and check the upload error if one appears.

Screenshots are required. Apple's specification page, checked 8 November 2026, says you upload 1 to 10 screenshots per device size, as .jpeg, .jpg, or .png, with no alpha channel. To submit, you need at least one screenshot for iPhone with Dynamic Island (medium display). The accepted sizes on that row are:

  • 1179 × 2556, or 2556 × 1179
  • 1206 × 2622, or 2622 × 1206

If the app runs on iPad, you also need a 13-inch screenshot at 2064 × 2752 or 2048 × 2732, portrait or landscape as listed. The same page says that starting in April 2027, iPhone Duo screenshots will be required for apps that use the iOS 27.1 SDK or later. That is a future requirement. It is not the requirement for every submission on the day this page was checked. Read the specification again when you upload.

Guideline 2.3.3 says screenshots should show the app in use, not only a title card or a splash screen. Capture Today with one fictional win, All wins with a completed line, and About. Three honest shots are better than ten marketing posters.

22Metadata, age, and privacy

Apple's platform-version table sets the lengths. Description is required, plain text, up to 4000 characters. Keywords are required, up to 100 bytes, and each keyword must be longer than two characters. Do not repeat the app name. Promotional text is optional, up to 170 characters, and can change without a new binary. Copyright is required: the year and the rights holder. Support URL is required and must lead to real contact information, a legal address, email address, or telephone number, as local law may require. Marketing URL is optional. Privacy Policy URL is required for iOS apps, and guideline 5.1.1 also requires the policy inside the app in an easy-to-find place. The About screen is that place. Version 1's policy can say the checklist stays on the device, the developer does not receive the list, and how a person can delete it (remove the app, or use Erase inside the app).

The support page will be public. Use a contact method you are willing to publish. This course does not host that page and does not want your home address in its notes box.

Age rating is a questionnaire in App Store Connect, not a number you invent. Apple translates your answers into a global rating and regional ratings where required. For a checklist with no restricted content, answer each frequency honestly, including "none". Guideline 2.3.6 says a wrong rating can surprise people and can draw regulators. Guideline 2.3.8 reserves phrases such as "For Kids" for the Kids Category. Do not put those words in the name unless you mean to meet the Kids rules, which are stricter.

Category is your best description. Productivity is the closest fit for a checklist. Guideline 2.3.5 says Apple may change a category that is far off. Read the category definitions before you submit.

App privacy details, the nutrition label on the product page, are required for new apps and updates. Include every SDK you ship, not only code you typed. If the app does not collect data off the device, the honest answers are short. Do not add an analytics SDK "for later" and then answer that you collect nothing.

Privacy manifests, required-reason APIs, and tracking

A privacy manifest is a PrivacyInfo.xcprivacy file. Apple's manifest document says it records collected data types and, on iOS, the required-reason APIs the app or SDK uses. Third-party SDKs on Apple's required list must ship their own signed manifest. The required-reason categories in Apple's technical note include active keyboards, disk space, file timestamps, system boot time, and user defaults. User defaults is ordinary preference storage. Your job is not to invent a reason code. If App Store Connect emails you that a manifest or a reason is missing, open the named library's current documentation and Apple's list, then upgrade or declare the reason that list actually contains.

Tracking, in Apple's terms, is linking data about a person with data from other companies' apps or sites for advertising, or sharing data with a data broker. A local checklist does not do that. If you later add a tracker that does, you need the App Tracking Transparency permission before tracking, and guideline 5.1.2 says the app may not require that permission in order to function. Version 1 should not show the tracking prompt at all.

23Accounts, deletion, and review access

Guideline 5.1.1 (v) says that if the app does not have a significant account-based feature, people should be able to use it without a login. One Small Win qualifies. Do not add a login to look serious.

If you later add account creation, the same guideline and Apple's account-deletion article require an in-app way to start deletion of the account and the personal data that goes with it. Hiding the control, or only offering "deactivate", does not meet the article. If the last step happens on a website, the app must link directly to that page. Tell the person if some records must be kept for a legal reason, and how a subscription cancellation is handled. Build the deletion path before you submit the version that creates accounts.

Guideline 2.1 says a review submission should be a finished build. Placeholder text and empty websites should be gone. If the app has a login, include a demo account that does not expire, and make sure the backend is on. If you cannot provide a demo account because of a legal or security duty, Apple allows a built-in demo mode only with prior approval, and that mode must show the full functionality. The review-contact name, email, and phone number are required App Review information. They are not shown on the product page. Enter the phone in international format with a leading plus and country code. Apple's own example of the format is a Hong Kong number prefix, +852. Use your real review contact, and keep it out of screenshots.

24Export and encryption questions

This section is a map of Apple's forms. It is not legal advice and not a classification of your app. Export rules depend on what encryption you actually ship and where you distribute.

Apple's documentation table, checked 8 November 2026, sorts apps three ways:

  • Encryption limited to what the Apple operating system provides: no documentation uploaded in App Store Connect.
  • An industry-standard algorithm that is not the one inside the Apple operating system: upload a French encryption declaration if you distribute in France.
  • A proprietary algorithm that standards bodies have not accepted: upload a U.S. CCATS and, if you distribute in France, the French declaration.

HTTPS that the system provides is the first row for many simple apps. Adding your own cryptography moves you to a different row. Answer the questions in App Store Connect for the binary you uploaded. Apple says it reviews complete documentation case by case and expects about two business days when the packet is complete. That sentence is Apple's expectation for the encryption review, not a promise about App Review as a whole, and not a promise that an incomplete packet moves at that speed.

If documentation is not required, Apple says to set ITSAppUsesNonExemptEncryption in the information property list so TestFlight and the store do not ask every time. Expo's production-build tutorial says the first eas build asks whether the iOS app uses only standard or exempt encryption. Pressing yes, for an app that does not add its own encryption, writes ITSAppUsesNonExemptEncryption: false. The snippet in this course includes that key for the local checklist. If your app's answer is different, remove the key and answer the prompts. A wrong "no" is worse than an extra question.

25TestFlight

TestFlight is the supported way to put a beta on a phone. Guideline 2.2 says demos and trial builds do not belong on the public store. Apple's TestFlight overview, checked 8 November 2026, is specific about the limits this course will quote:

  • You can test a build for up to 90 days. After that, the build is unavailable to testers.
  • Internal testers: up to 100 people who are App Store Connect users with access to your content. They can test for 90 days. Internal testing uses those accounts, so it is the wrong tool for a large public beta.
  • External testers: up to 10,000 people. The first build you add to an external group is sent to App Review. A review is required for that first build. Later builds may not need a full review. Testing starts after approval.
  • The build must include an application identifier in its provisioning profile.
  • Managed Apple Accounts on reserved domains cannot be used as testers.

Testers install Apple's free TestFlight app and accept an email invite or a public link. You write "What to Test" when you add a build. For One Small Win, that note can be: add a line, force-quit, confirm the line remains, try the largest text size. Crash feedback from TestFlight testers appears under TestFlight, Feedback, Crashes. Apple says those crash reports are available for download for 120 days.

Internal-only uploads cannot be sent to external testers or to customers. Read the badge on the build. If you only need yourself, an internal group is enough and skips the external beta review until you want outsiders.

26Build, upload, review, release

Stay on the Expo route for these commands. The Mac archive path is the last subsection, and it uses Xcode instead.

Cloud build and upload

Install the CLI and sign in to Expo. Expo's docs still call the CLI eas even though the service is now named Expo Build.

npm install --global eas-cli
eas login
eas build:configure
eas build --platform ios

The first iOS build asks you to sign in to Apple if credentials do not exist yet, and it asks the encryption question from the previous section. When the build succeeds, Expo keeps the .ipa. Submit it with:

eas submit --platform ios

Expo's submit page says this works on Windows. It also says the build shows up in TestFlight after processing, usually 10 to 15 minutes. That duration is Expo's description of processing, not an Apple service agreement. If processing takes longer, wait and read the status in App Store Connect rather than uploading a second identical build. A later shortcut on Expo's page is eas build --platform ios --auto-submit. The production tutorial says that uploads to TestFlight and does not itself submit the store review. You still open App Store Connect for metadata, screenshots, and the review button.

Expo's pricing page, checked the same day, lists a Free plan at 0 USD per month with up to 15 Android builds and 15 iOS builds, on a low-priority queue. The billing FAQ says a free account is not charged overage; when the monthly quota is used, new builds wait until the next calendar month. Paid Expo plans exist (the pricing page listed Starter at 19 USD per month plus usage, and Production at 199 USD per month plus usage). Those prices are optional speed and capacity, not an Apple requirement. Read the pricing page again before you subscribe. A low-priority wait is not a failure.

The store submission

In App Store Connect, open the iOS version. Attach the processed build. Finish screenshots, description, keywords, support URL, privacy policy URL, copyright, age questionnaire, and privacy details. Choose a release option. Apple's release page offers three: release it yourself after approval, release automatically after approval, or release automatically no earlier than a date you enter. If the app is in pre-order setup and has never been released, Apple selects manual release for you.

Submit for review. Guideline 2.1 is the standard: the build runs, the links work, and the notes explain anything a reviewer cannot see. For this app the notes can say there is no login and the list stays on the device. If review sends questions, answer in App Store Connect. If they reject the build, the message cites a guideline. Change the app or the metadata to match that citation, increase the build string if the binary changed, upload, and submit again. A rejection is a review outcome. It is not a statement about you.

Apple's release page does not promise how long review takes. The clock it does state: after you manually release a version that is Pending Developer Release, it may take up to 24 hours to appear on the store. Apple also emails you if a version sits in Pending Developer Release for more than 30 days. Automatic release goes out after approval without that extra click. Phased release, for an update, spreads an automatic update over 7 days. It is optional and does not apply to the brand-new first release in the same way. Read the control you are looking at.

Mac archive path, only if you chose Xcode

On a Mac, with the SwiftUI target, use Xcode's run button and the Simulator until the checklist behaves. Then use Xcode's archive and distribute flow in Apple's distribution documentation. This environment has no Mac, so this course does not pretend to have clicked through Xcode 27's menus. The labels in your Xcode and Apple's document are the instructions. You still end in App Store Connect with the same metadata, TestFlight, and review steps. Signing on this path is Xcode's automatic signing or profiles you create in the developer account. You do not also run eas build for the same binary.

Checkpoint. You can describe the path as files, then a signed build, then processing, then TestFlight, then a review submission, then a release click or an automatic release. You are not owed a date.

Ship version 1 free, with no in-app purchase. You can learn the store without also learning tax forms and purchase restoration. When you do charge, Apple's rules depend on what you are selling and where the buyer is. The percentages below are the ones on Apple's public pages on 8 November 2026. The contract in your account, for the storefront where the sale happens, is the number that applies. Do not add these percentages together.

28Copies, scams, templates, and AI

Apple's design rules are the usual reason a first wrapper is rejected. The sentences below are the parts that apply to a beginner project. The guideline page is the full text.

  • 4.1 Copycats. Come up with your own idea. A small change to a popular app's name or screens is a copy. Using another developer's icon, brand, or product name in your icon or name, without their approval, is called out separately.
  • 4.2 Minimum functionality. The app should include features, content, and UI that elevate it beyond a repackaged website. If it is not useful, unique, or app-like, it does not belong on the store. A single checklist with real on-device behavior is a stronger submission than a website inside a frame. It can still be rejected if the reviewer finds it not useful enough. There is no checklist that forces an approval.
  • 4.2.2. Other than catalogs, apps should not be mainly marketing, ads, web clippings, or a collection of links.
  • 4.2.6. Apps from a commercialized template or app-generation service are rejected unless the provider of the content submits them, and the tool must let each client make a distinct app. A vendor submitting many clients' clones is the case this rule describes.
  • 5.2.1. You need rights to trademarks, copyrighted material, and the other intellectual property in the app. Submit under the person or legal entity that holds those rights.
  • 2.3.1. Metadata has to describe the app you uploaded. Claiming a feature you do not have is grounds for removal.

An AI assistant can help you write a screen. It does not review the app, and it does not own the content it imitated. If the generated UI is a copy of a known product, change it before you submit. If the generated app is a web view plus a splash screen, expect guideline 4.2 to be the conversation. If the model offers to "wrap your website so it gets approved", that offer is the risk, not a plan. You click the submit button. The rejection, if it comes, is on the binary you sent.

29After it is on the store

A released app needs a person who reads mail. The support URL is that promise. Plan a simple habit: check the inbox you published, and check App Store Connect, on a schedule you can keep. Silence is an acceptable product result. Ignoring a crash you already know about is not.

TestFlight crash feedback is described above and kept for 120 days. For the public build, use the crash information Apple shows for that app in App Store Connect and in Xcode, and read Apple's current crash-log document when you open one. A crash report is a stack trace. Match the version and build in the report to a commit in Git before you change code. Fix one crash, raise the version or at least the build string, write What's New in plain language (required for versions after the first, up to 4000 characters), and submit the update through the same review path.

App Store Connect includes sales and analytics for the store listing. That is Apple's data about downloads and sales. A third-party analytics SDK is a different decision: it can be personal data, it belongs in the privacy questionnaire and the privacy policy, and tracking across other companies' apps needs App Tracking Transparency. Version 1 of this course's sample does not add one. Add it only when you can name the question the numbers will answer.

Keep the privacy inventory from the template next to the project. When you add a library, add a row the same day. The row says what it collects, whether it leaves the device, and which App Store privacy category you will tick. That inventory is how the nutrition label stays true.

34When something breaks

node is not recognized
Open a new terminal. If it still fails, reinstall Node LTS and allow it to change PATH. Then run node -v again.
The phone says the project is incompatible with Expo Go
The SDK in package.json and the SDK inside Expo Go are different. Read Expo's mismatch page before you edit versions. Use the web preview, Android, a Mac simulator, a development build, or the eas go path that page documents.
The QR code does nothing
Same Wi-Fi first. On an iPhone, the same Expo account on the computer and in Expo Go. Then try npx expo start --tunnel.
Unable to resolve module
The import path and the file name disagree, or the package is missing. From the project folder, run npx expo install for that package. Check that wins.ts is at src/lib/wins.ts.
The screen ignores my edit
Confirm you saved the file you think you saved. Restart with Ctrl+C and npx expo start --web. Fast Refresh's toggle is in the developer menu.
Apple or Expo will not create a certificate
Confirm the membership is paid and that your role may create certificates. Read the error. Do not delete an existing distribution certificate until you know which apps were signed with it.
The upload sits in processing
Wait, and read the status. Expo describes a usual 10 to 15 minutes. Apple does not guarantee that interval on the page this course cites. A second upload of the same build string will not speed the first one up.
Screenshot rejected for size or alpha
Export a PNG or JPEG at 1179×2556 or 1206×2622 with no transparency. The specification page lists the other accepted sizes if you are uploading a different device class.
Review cites 4.2
The reviewer saw a thin wrapper or too little utility. Add the on-device behavior your spec promised, or narrow the app until that behavior is obvious. Update the screenshots so they show it. Resubmit with notes that say where to tap.
TestFlight build expired
90 days from upload. Make a new build, with a new build string, and add it to the group.

35Ten-minute tasks

Use these when you do not have an hour. Each one ends with something you can see.

  1. Add one win in the practice panel. Refresh. Confirm it is still there.
  2. Write the success test for your own idea in a single sentence.
  3. Sketch Today empty and Today with one item.
  4. Run node -v and write down the number.
  5. Change the empty-state sentence, save, and find it on the screen.
  6. Make one Git commit and run git log --oneline.
  7. Read guideline 4.2 out loud once. Decide whether your current build is more than a website frame.
  8. Fill the privacy inventory with "none" everywhere that is true.
  9. Measure your icon file. It should be 1024 by 1024 before you depend on it.
  10. Install your TestFlight build, if you have one, and force-quit it. That single check is the release test.

When a ten-minute task is done, you are further along than you were. The store listing can wait until several of them are true on a phone.
