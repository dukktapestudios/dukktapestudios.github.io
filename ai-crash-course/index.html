AI Crash Course

A plain-language beginner's guide to how AI works, how local chat and image tools fit on a typical gaming PC, and how those pieces can later connect into a talking desk robot. The example character is named Cody. Go at your own pace. This is a starting map, not a test.

A learning guide. Ollama, Forge, llama3.1:8b, and Juggernaut XL are common example tools. Hardware mentions, such as a typical gaming PC (for example, an 8 GB GPU), are examples too. This page does not describe one person's computer.

01Welcome

A computer-science background is not required to start working with AI. A practical starting setup is a chat tool and an image tool on the computer in front of you. Two common free local options are Ollama for chat (for example, the llama3.1:8b model) and Forge for images (for example, the Juggernaut XL model).

This page explains the ideas in everyday language, with simple analogies. It is meant to support two goals: learning enough to make side money over time, and seeing how an example character named Cody could become a desk robot, and later a drone. Read a section, try one small exercise, and come back later.

Local text AI

Chat, on a computer

Ollama with llama3.1:8b. You type, it replies. With a local install, the chat does not have to leave the computer.

Local image AI

Images, on a computer

Forge with Juggernaut XL. You describe a picture, it generates one.

Example hardware

A typical machine

A typical gaming PC (for example, an 8 GB GPU and 16 GB of system RAM) is enough for the 7B and 8B class models this guide starts with.

Small wins beat rushing. There is no need to learn everything in one sitting. One clear experiment, like a better prompt or a picture of Cody that actually looks right, is a complete success for a day.

02What AI actually is

Artificial intelligence (AI) is a broad name for software that can do tasks that used to need human judgment, such as writing, recognizing speech, or making an image from a description. It is not a person, and it does not understand the world the way a person does. It is a tool that has learned patterns from large amounts of data.

Machine learning is how most modern AI is built. Instead of a person writing a rule for every situation, the system is shown many examples and adjusts itself until it gets better at a task. A useful analogy is learning to recognize a friend's handwriting: nobody hands you a complete rulebook. Enough samples, and the pattern starts to click.

A neural network is the most common design for that learning. Think of a huge stack of tiny decision-makers, each passing a slightly processed signal to the next. During training, the connections between them are tweaked so the final output gets closer to the right answer. The math is not required to use the tools.

A large language model, or LLM, is a neural network trained to predict the next piece of text. Chat models are LLMs that have also been shaped to answer questions and follow instructions. They are very good at sounding fluent. Fluency is not the same thing as being right.

Core ideas
IdeaPlain meaningEveryday analogy
Token A small chunk of text the model reads and writes, often a word or part of a word. Lego bricks. The model builds a reply one brick at a time.
Training The slow, expensive process of teaching a model from huge amounts of data. This usually happens in a data center, not on a home computer. Years of study, done once, before the tool reaches anyone.
Inference (use) Running an already-trained model to get an answer, an image, or a voice clip. This is what Ollama and Forge do. Using what was already learned to answer a new question.
Parameters / model size The learned settings inside the model. Size is often written as 8B, meaning about 8 billion parameters. The number of adjustable knobs. More knobs can mean more capability, and they also need more memory.

Why llama3.1:8b fits an 8 GB GPU: an 8 billion parameter model is a middleweight. Ollama typically runs a quantized (compressed) copy, which shrinks the memory needed. A typical gaming PC (for example, an 8 GB GPU) has enough dedicated graphics memory, called VRAM, for a common 4-bit 8B chat model. Much larger models often do not fit, or they run slowly by spilling into regular RAM. That is why staying around the 7B to 8B range is a practical starting point on that kind of machine.

03How chat assistants work

A chat assistant is an LLM plus some surrounding software that holds the conversation, may keep notes, and may let the model use tools. The pattern is the same whether the model runs on a local computer or in the cloud. What follows is the general idea, not the inner workings of any one product.

Pieces of a chat assistant
PieceWhat it doesWhy it matters
Prompt The text someone types, plus any instructions or examples included with it. Clearer requests usually get clearer results. Garbage in, garbage out still applies.
Context window The model's short-term memory for this conversation: the messages, the replies, and other attached text, up to a size limit. If the chat gets long, earlier details can fall off the edge. Important facts may need to be restated.
System instructions Standing directions given to the model, such as "reply briefly" or "you are a helpful desk assistant named Cody." This is a common way to shape tone and behavior without retraining the model.
Tools / function calling The model can request an action, like looking something up or calling a program, instead of only writing text. This is how a chat model can later control a robot, a document, or a search, rather than just talking about it.
Memory Optional longer-term notes saved outside the current chat, then brought back later. A model does not automatically remember a person between sessions unless the app saves something on purpose.
Agents A setup where the model can plan steps and use tools to try to complete a task, not just answer one question. Powerful, and also easier to get wrong. Start with simple, supervised steps.

They can be wrong. Models sometimes invent facts, sources, quotes, or details that sound confident. This is often called a hallucination. Always check anything important against a real source: a receipt, an official page, a person who would know. If it matters for money, health, legal issues, or hardware, do not take the model's word alone.

04Types of AI

"AI" is not one program. Different models do different jobs. They can be combined later, which is how a talking Cody would work.

Kinds of model
TypeWhat it doesExample to try
Text (LLM) Writes, explains, brainstorms, and helps with code or plans. Ollama with llama3.1:8b, a common local starting model.
Image (diffusion) Starts from noise and gradually shapes it into a picture that matches a description. Forge with Juggernaut XL, a common local image setup.
Speech-to-text Listens to audio and turns it into written words. Whisper is a widely used open model for this.
Text-to-speech Turns written words into a spoken voice. Piper is a popular option that can run locally.
Vision Looks at an image or camera frame and describes or interprets it. Some chat models can accept a picture as well as text. A desk robot could later use a small camera.

Diffusion, in plain terms, is like a sculptor starting with static on a TV and slowly nudging it toward the picture described. That is different from a chat model, which predicts the next bit of text.

05Local vs. cloud

Local AI runs on a computer you control. Cloud AI runs on a company's computers and is reached over the internet. Ollama and Forge are examples of the local path. Many people use both: local for private or unlimited practice, cloud when they want a larger model or a polished app.

Local (a computer you control)

  • Chats and images can stay on that computer.
  • No per-message fee once the software and model are installed.
  • No monthly usage cap from a vendor. The limit is the hardware.
  • Works without an account, and can work offline after the model is downloaded.

Cloud (a company's servers)

  • Often stronger at hard reasoning, writing, and coding, because the models are larger.
  • Easy to start: a website or app, no install required.
  • Prompts usually go to someone else's servers, so privacy depends on that company.
  • Paid plans, usage limits, or per-use bills are common.

Speed depends on the task and the hardware. A local 8B chat model can feel snappy on an 8 GB GPU. A big cloud model may be smarter but is also only as fast as the internet connection and the provider's servers. Local image generation has the same tradeoff: it works, and each image takes some time.

They can work together. A practical split is: use local tools for private notes, practice, character work, and anything that should stay in the house. Use a cloud assistant when extra help thinking or coding would be useful, and still keep secrets off the internet.

06Hardware basics

The graphics card (GPU) is what makes local image and chat models practical. A GPU has many small cores and its own fast memory, called VRAM. The model generally needs to fit in VRAM, with some room left for the conversation or the image being built.

Think of VRAM as the workbench. If the project fits on the bench, work goes quickly. If it does not, pieces spill onto the floor (regular system RAM, or even the drive), and everything slows down. On a typical gaming PC (for example, an 8 GB GPU), that 8 GB is the workbench. 16 GB of system RAM is a common amount and is helpful, but it is not a substitute for VRAM when speed matters.

Quantization is a way to compress a model so it uses less memory. Labels look like Q4, Q5, or Q8. Lower numbers usually mean a smaller file and lower VRAM use, with some quality tradeoff. Higher numbers are closer to the full model and need more memory. Ollama often ships a quantized version by default, which is a big reason an 8B model can run on an 8 GB card.

  • If a model is too large, it may fail to load, or it may run very slowly.
  • If a bigger model makes the computer crawl, go back to the 7B or 8B range. That is not a failure. It is matching the tool to the hardware.
  • A new computer is not required to start. A typical gaming PC (for example, an 8 GB GPU) is already enough for the path laid out here.

07Costs

There are three common ways to pay for AI. None of them is automatically best. It depends on how the tools are used.

Ways to pay
Way to payHow it worksGood to know
Local (example setup) The computer and electricity are the costs. Installed local models do not charge per prompt. Best for practice, private work, and lots of trial and error. Time and the power bill are the ongoing costs.
Subscription A flat monthly (or yearly) fee for a cloud assistant or app, often with a usage limit. Predictable bill, but cap days still happen. Monthly billing is easier to cancel than a long prepaid year when the goal is only to try it.
API, pay per use A person or a program sends requests to a company's model and is billed by usage, often by tokens. Useful later if an app is built. A bug that loops can get expensive, so this is not the first step.

More money is not required to learn the basics. Use local tools first. If a cloud plan is added later, start with a monthly tier and watch how much it is actually used.

08Prompting basics

A prompt is the request. Good prompts are specific about the goal, the audience, the length, and the constraints. An example of the style helps too. If the first reply is off, say what to change instead of starting from scratch every time.

Weaker prompts and stronger ones
Weaker promptWhy it strugglesStronger prompt
Write something about a robot. No audience, length, or purpose, so the model has to guess. Write a 3-sentence product description for a friendly desk robot named Cody. Plain language, no jargon, for someone who wants a small talking companion on a desk.
Make me a fox. Too vague for an image model. Pose, style, clothing, and background are all undefined. Full-body illustration of a friendly anthropomorphic fox character, standing, simple blue dress, plain light background, consistent character design, no text in the image.
Is this a good idea? The model does not know what "good" means here. I want a weekend project: hook a microphone to a computer and have Ollama answer out loud. List the first three steps, the likely pitfalls, and what to test before buying parts.
  • Say what the result should be, who it is for, and how long it should be.
  • For images, mention subject, pose, clothing, background, and style. Change one thing at a time when iterating.
  • Ask the model to show its assumptions, or to list what it is unsure about, when the answer matters.
  • For facts, ask for sources, then check those sources. Made-up citations happen.

09How the pieces connect

An API is a standard way for programs to talk to each other, like a counter window at a shop: a clear request goes in, and a structured reply comes back. Ollama offers a local API, usually at http://localhost:11434, on the computer where Ollama is installed. Forge can be used from a browser, and it can also be set up to accept requests from other programs. Official details are in the Ollama API introduction.

Python is a popular programming language for gluing these pieces together. Being a programmer is not required to chat in Ollama or make images in Forge. When it is time to connect a microphone, a voice, or a small electronics board to the model, a short Python script is a common way to do it. The official Python tutorial is the right starting place, and it can be learned a page at a time.

A desk robot does not replace the computer as the brain at first. The robot is the body: a microphone, a speaker, a small screen, and maybe a couple of motors, often wired through an ESP32 or similar board. The computer does the heavy thinking.

Build this in layers. First, make the loop work on the computer alone (microphone to text, to Ollama, to speakers). Then add a face on the screen. The physical desk robot comes after that loop is reliable. That order saves money and frustration.

10Safety and privacy

Treat a cloud AI chat like a postcard that a company may be able to see. Local tools like Ollama and Forge are much more private, because the work can stay on the computer, but it is still worth being careful about what gets saved and shared.

  • Never paste passwords, Social Security numbers, PINs, seed phrases, or full account numbers into a cloud AI. Last four digits are enough if an account ever needs to be referred to.
  • Be wary of scams that use AI. Common patterns include cloned voices of relatives asking for money, fake job or "AI business opportunity" pitches that promise easy income, and phishing messages that look unusually polished.
  • Deepfakes are realistic fake images, video, or audio. Do not make or share non-consensual fakes of real people. Be skeptical of shocking clips, especially if they ask for money or personal data.
  • If a scam seems likely, it can be reported to the U.S. Federal Trade Commission at ReportFraud.ftc.gov.
  • Report a scam or fraud to the FTCreportfraud.ftc.gov

11Limits and checking facts

AI is useful, and it is also uneven. Knowing the limits saves time and trouble.

  • Bias. Models learn patterns from data that can be incomplete or skewed. They may treat people or topics unfairly, or repeat stereotypes. Read answers with that in mind, especially on sensitive subjects.
  • Outdated or missing knowledge. A model only knows what it was trained on, plus anything the app retrieves for it. It can miss recent changes, or invent a confident answer when it does not know.
  • Verify important answers. For money, health, legal questions, school, hardware purchases, and anything that will be published, check a primary source: official docs, a statement, a real person, or records kept for that purpose.

A healthy habit is to ask, "How would I check this if the model were a confident stranger?" If it cannot be checked, do not treat it as settled.

12Copyright and licensing

This is not legal advice, and the rules are still developing. Before selling something, read the official sources and the rules of the site that will be used. When a lot of money or someone else's work is involved, consider talking to a lawyer.

In the United States, the Copyright Office's January 2025 report on copyrightability (Part 2 of its Copyright and Artificial Intelligence report) includes these points, in plain language:

  • Using AI as a helper, rather than as a stand-in for human creativity, does not automatically cancel copyright in what was made.
  • Copyright protects original expression created by a human, even if the work also includes AI-generated material.
  • Copyright does not extend to purely AI-generated material, or to material where a person did not have enough control over the expressive parts.
  • With the generally available tools in use at the time of that report, prompts alone were not considered enough control.
  • A person may have copyright in their own creative contributions that are perceptible in the output, and in a creative selection, arrangement, or modification of the output. Each case depends on the facts.

Licensing is a separate issue from copyright in the output. Models and some platform tools come with licenses that can restrict commercial use, certain kinds of content, or how the model is shared. Open-weight does not automatically mean "do anything." Read the license for llama3.1 and for Juggernaut XL (and any other model that gets added) before selling work made with them.

Code help from a model can also include snippets that resemble existing projects. Do not paste generated code into a project that will be sold or published until it is understood and licensing has been considered. When selling art, check the current rules of each platform, including whether they require disclosure of AI use. Do not copy living artists' names as a style shortcut for commercial work, and do not use other people's copyrighted characters or logos in products for sale unless the right to do that exists.

Training-data copyright (whether a model was allowed to learn from certain works) is a separate, still-active legal topic. The Copyright Office has been writing about that too. Do not assume it is settled.

13Ethics and responsible use

The technical skill is only half of the work. How the tools are used matters.

  • Do not use AI to scam, impersonate, harass, or trick people.
  • Do not create or spread non-consensual deepfakes of real people.
  • Be honest when it matters: with clients, on a selling platform, or in school work, say when AI helped if the rules or a reasonable person would expect that.
  • Do not present made-up facts, fake reviews, or fake credentials as real.
  • Respect other people's privacy, including in photos, voice recordings, and personal stories that might be fed into a tool.
  • Think before publishing. A picture or paragraph that felt like a joke can still hurt someone once it is online.

14Ways to earn, without the hype

AI can help work go faster. It does not replace the need for a good offer, decent quality, and patience. Be skeptical of anyone selling a course or system that promises easy income with AI. That pitch is a common scam pattern.

  • Make things that already matter, then use the tools to help.
    • Forge can help draft card art, stickers, or printables, which then get refined and checked for licenses, and sold only if the model license and the platform allow it.
    • A chat model can help write a clearer listing, a packing list, or a first draft of a description. A person still edits and fact-checks.
  • Learn in public by building small, real projects, such as a talking Cody on a computer.
    • Finished projects teach more than theory, and they can later become a portfolio if the goal is to offer help to others.
  • What usually does not work
    • Mass-uploading raw AI images and hoping they sell themselves.
    • Paying upfront for a "done-for-you AI business" that guarantees earnings.
    • Copying someone else's characters or brand and putting them in a shop.

A realistic bar. Treat early sales, if they happen, as a bonus while skill is built. The near-term win is being able to use the tools with confidence. Side income is more likely after work can be finished and polished, not after the first weekend.

15Key terms you will see

Terms that show up next
TermPlain meaning
RAG (retrieval-augmented generation) The system looks up relevant notes or documents first, then the model answers with that material in view. Like allowing an open-book test instead of forcing the model to recall everything.
Embeddings A way of turning text (or images) into a list of numbers that captures meaning, so similar items land close together. This is often what powers search in a RAG setup.
Fine-tuning Extra training on a set of examples so a model specializes. This is usually a later step. For Cody's personality, clear instructions and examples are often enough at the beginning.
Agents A setup where the model can plan and use tools to pursue a goal, such as "draft a reply and look up a fact." Start simple, and keep a human in the loop for anything that sends a message, spends money, or moves hardware.
Tool use / MCP Tool use means the model can request an action, not just write text. MCP (Model Context Protocol) is a common standard for connecting an assistant to tools and apps in a consistent way.
Open-weight vs. closed Open-weight models let someone download the model files and run them, the way llama3.1:8b runs in Ollama. They still have licenses. Closed models stay on a company's servers. People use them through an app or API and do not get the files.

16Common beginner mistakes

  1. Writing vague prompts and deciding the tool is useless after one try.
  2. Trusting a fluent answer without checking the parts that matter.
  3. Pasting passwords, ID numbers, or account details into a cloud chat.
  4. Starting with a model that is too big for the GPU, then assuming local AI does not work.
  5. Trying to learn every course, tool, and buzzword at once instead of finishing one small project.
  6. Expecting the first image or first robot idea to be final. Iteration is the normal path.
  7. Selling AI work before reading the model license and the platform's rules.
  8. Paying for expensive "AI side hustle" programs before using free local tools such as Ollama and Forge.
  9. Assuming a local 8B model is just as capable as the largest cloud models. It is useful and private. It is not the same thing.
  10. Buying robot parts before the talking loop works on the computer by itself.

17Healthy habits

AI is a helper. It is not a replacement for friends, family, or professional advice. It should not be a doctor, lawyer, therapist, or financial advisor.

  • Use it to draft, practice, and explore, then apply judgment.
  • Stop for a break after prompting in circles. A short walk often helps more than ten more retries.
  • One finished exercise is enough for a session. A project can stay half-done until tomorrow.
  • If a topic is heavy, it is okay to switch to something concrete and small, like a Forge test or a short Ollama question that can be checked.
  • Keep some work offline and some time offline. The tools will still be there.

18A first-week learning path

These are suggested hands-on exercises, not a live checklist. Do them in any order, and skip a day if needed. Each one is meant to be a complete win by itself.

  1. Have a real chat in Ollama. Open a terminal and run ollama run llama3.1:8b, or use the app window that comes with the install. Ask it to explain something already known well, and notice what it gets right or wrong.
  2. Catch one mistake on purpose. Ask a factual question that can be verified (a date, a public official page, or a setting in a program that can be checked). Check the answer. The point is to feel, firsthand, that confident is not the same as correct.
  3. Rewrite one weak prompt. Take a vague request and turn it into a stronger one using the table above. Compare the two replies.
  4. Make three related images in Forge. Generate the same Cody-like character three times, changing only one detail each time (pose, clothing, or background). This teaches control better than starting over with a brand-new idea each time.
  5. Skim the Ollama quickstart. Read the official quickstart so the docs are easy to find later, including the local API address.
  6. Optional: start the Python tutorial. If the next goal is to hook tools together, do the first few pages of the official Python tutorial. Stop after one sitting. The book does not need to be finished this week.
  7. Sketch the Cody loop on paper. Draw the path: microphone, then speech-to-text, then Ollama, then text-to-speech, then speaker and screen. No parts required. This is the blueprint for the desk robot.

After that week, go deeper with free, reputable courses. Start with Elements of AI for a gentle foundation with no programming. Save Google's Machine Learning Crash Course, fast.ai, and the Hugging Face course for after the basics feel comfortable and, for the later two, some Python.
